The SimpleVTT roll-log v2.43.0

Every action at the virtual table — a die roll, a weapon swing, a spell cast, a class feature use — produces a card in the roll-log drawer on the right side of the tabletop. v2.43.0 simplified the layout: one display mode (no more "Compact: ON/OFF" toggle), one outcome row of oversized pills per card, header chips for target + classification, and inline meta + descriptions so the eye scans who → what → outcome without diving into a drop-down.

Card anatomy

Every card variant shares the same three-zone structure: a header strip (avatar, caster name, target chip, classification chip, time); a body row (spell or feature name + inline meta or description); and an outcome pill row when auto-resolution fired. A collapsible ▾ details toggle tucks long flavor / dice breakdown out of the way; the headline + pill row alone carry the at-a-glance read.

1 · roll — plain dice roll

Emitted by /roll. Headline = total + short note. Expression + breakdown live in ▾ details. Sample above.

2 · weapon_attack — /attack endpoint result

Carries the attack roll and the damage roll inline (the dice ARE the at-a-glance point of an attack card, so a pill row would just duplicate them). Hit / miss / crit verdict is a badge on the attack line. When auto-apply-damage is on, the damage line shows the HP delta and the ↶ Undo button.

3 · spell_cast — single layout, outcome pills

Target tag in the header (next to the slot chip). Spell name + meta (school · casting time · range · Concentration · Ritual) inlined on a single body row. Every auto-resolution outcome — heal, attack verdict, damage applied, save prompt or rolled save, condition install, save-for-half damage, Undo — is its own oversized pill, color-coded by consequence type.

Auto-resolution suppresses redundant buttons

When the server's auto-resolution path (campaign-toggled Auto-apply damage) already rolled the spell's attack / save / damage / heal, the manual "🎲 Roll damage" / "📋 Prompt save" / "🩹 Apply Healing" buttons on the spell-cast card are not rendered. The outcome is in the pill row + the ↶ Undo pill.
  • auto_heal_applied > 0 → "🩹 Apply Healing" button hidden
  • auto_attack_hit != null → "🎲 Roll {damage}" button hidden (regardless of hit/miss)
  • auto_save_target_kind != null → "📋 Prompt save" + "🎲 Roll damage" buttons hidden

Spells with no auto path (Magic Missile auto-hits, utility spells) keep their manual buttons. When the manual damage button does fire, it now attributes the roll to the caster (not the user's primary PC) and hides itself on a successful roll (v2.42.2 / v2.42.3 fixes).

Themes — the pills adapt

The pill borders + summary colors derive from CSS custom properties so all eight built-in themes re-tint without per-theme overrides. Outcome semantic colors stay consistent (heal=green, damage=orange, crit=amber, buff=cyan, miss=danger); only the layout accents follow the theme.

Persistence + visibility

Roll-log cards survive page refreshes via localStorage (key simplevtt:rolllog:${CAMPAIGN_ID}, last 100 WS-only entries, FIFO trim).

Each roll event carries a visibility field:

  • public (default) — everyone in the campaign
  • gm_and_roller — GM + the rolling user; card has an amber "GM + you" badge + border
  • gm_only — GM only; danger-colored "GM only" badge + border

weapon_attack / spell_cast / feature_used are always public.

Where the code lives

  • Card rendering: app/static/tabletop.js — appendRoll, appendSpellCast, _appendFeatureUsed, appendWeaponAttack, appendRollRequest.
  • Outcome pill row: same file — _spellResultPillsHtml(d). Reads the auto-resolution fields off the cast payload and emits one pill per consequence.
  • Persistence: same file — _persistRollEntry + _hydrateRollLog.
  • Pill + inline-meta CSS: app/templates/tabletop.html — .result-pill, .result-pills, .spell-cast-name-row, .spell-cast-meta-inline, .feature-used-name-row, .feature-used-desc, .feature-used-counter.
  • Theme tokens (--c-heal / --c-crit / --c-damage / --c-buff): app/static/style.css.
  • Dice toast (separate transient surface): app/static/roll_toast.js.
  • Heal-pill broadcasts: app/routes/tabletop_routes.py use_second_wind + use_lay_on_hands set heal_amount / heal_target_name / heal_hp_before / heal_hp_after on the feature_used broadcast.
