Targeting system guide v2.49.168

Visual reference for SimpleVTT's canvas target picker — how players and the GM pick spell / attack targets on the map, what the green / red / amber rings mean, how range is gated client-side and enforced server-side, and how the three picker modules (_targetPicker, _aoePicker, _rulerPicker) differ. Worked examples for single-target spells, multi-beam stacking (Magic Missile, Eldritch Blast), AoE placement (Fireball), and melee weapon attacks.

How the picker works at a glance

When a player clicks 🗡 Strike, ✨ Cast, or a feature button on the character sheet (or, for NPCs, 🗡 Strike in the init tracker), and no target is already pre-selected via canvas double-click, the canvas picker opens. The player sees:

  • A green dashed ring around every in-range token that's a valid target.
  • A crimson ring + glow on the token currently under the cursor (if in range).
  • An amber dashed ring + warning if the cursor hovers an out-of-range token.
  • A ruler line + distance chip from the caster's token to the cursor (suppressed for melee ≤ 5 ft).
  • A "×N" badge on tokens picked more than once (for stacking — Magic Missile, Eldritch Blast).
  • A floating hint at the top of the canvas: "🎯 Spell · pick 0 / N targets · click target · right-click to undo · Enter to commit · Esc to cancel".
Anatomy of an active target picker. Caster (blue) → ruler line + chip → cursor on a crimson-highlighted hovered token. Green dashed ring marks an available in-range token; amber dashed marks an out-of-range one; previously-picked tokens carry a crimson ring + ×N badge.

Ring state legend

Every token visible to the picker is in one of these states. The picker re-renders on every cursor move so states transition fluidly as you hover.

Range visualization — three regimes

How the picker visualises range depends on the spell / attack's reach.

1. Melee (range ≤ 5 ft)

The ruler line + distance chip is suppressed (v2.49.161+) because "5 ft / 5 ft" carries no useful information and visually clutters the one-cell decision. Only the green ring on the adjacent token marks the target.

Pip (caster) with Shortsword (5 ft reach). All 8 adjacent enemy tokens (Chebyshev distance = 5 ft) get a green ring. The enemy 10 ft away diagonally gets nothing. No ruler line.

2. Mid-range (e.g. 30–120 ft)

Full picker: green availability rings on in-range tokens, ruler line + distance chip from caster to cursor, amber preview when the cursor strays beyond range.

Zara casting Fire Bolt (120 ft). Three enemy tokens in range get green rings; the hovered one (right) flips to crimson. Ruler chip reads "60 ft / 120 ft" — comfortably in range. The far enemy outside 120 ft gets no ring at all.

3. Out of range (cursor or token beyond reach)

When the cursor enters an out-of-range cell or hovers an out-of-range token, the ruler line + chip flip to amber, the hover ring goes amber dashed, and the chip prefixes a "⚠" with the distance overrun.

Cursor on an out-of-range token (145 ft > 120 ft Fire Bolt range). Ruler goes amber, hover ring goes amber dashed, chip prefixes "⚠". A click here posts to the server which 409s with out_of_range.

Multi-target stacking — Magic Missile, Eldritch Blast

Spells that fire multiple darts / beams (Magic Missile, Scorching Ray, Eldritch Blast) ask for required = N picks where N is the number of darts / beams (with per-slot scaling and per-level cantrip scaling). The picker accepts the same token clicked multiple times — each click increments a ×N badge on that token. Right-click decrements. The picker auto-commits when the total equals required; Enter commits early.

Magic Missile L1 (3 darts). Left bandit gets 2 darts (×2 badge), right bandit gets 1 dart. Picker auto-commits at 3/3 → server iterates the combatant-id list [bandit_a, bandit_a, bandit_b] and rolls per-dart damage.

AoE picker (Fireball, Spirit Guardians, Spike Growth)

AoE spells use the second picker module — _aoePicker — which differs from the target picker in that you place a SHAPE on the map, not pick individual tokens. The picker draws the AoE outline (sphere / cube / cone / line) following the cursor with the caster's reach as the range gate. Same green-in-range / amber-out-of-range colour language.

Fireball cast. Caster center → cursor with the 20 ft radius sphere preview (orange dashed). Three enemies fall inside the AoE; clicking commits the placement and the server resolves the save vs damage for each enclosed combatant.

Data flow — from click to chat card

Client-side

1 User clicks 🗡 Strike / ✨ Cast → button handler reads data-attack-range / spell range.
2 Handler calls vttOpenMultiTargetPicker({required, casterCharId | casterCombatantId, rangeStr, spellName}).
3 Picker resolves caster's token center (PC: via character_id; NPC: via combatant_id → source_token_id / token_template_id+name).
4 Picker parses rangeStr ("120 ft", "5 ft", "30/120 ft") → rangeFt.
5 Picker renders green rings on in-range tokens (Chebyshev distance from caster center).
6 User hovers / clicks. addPick() increments badge; right-click removePick().
7 Picker auto-commits at required picks → resolves to Array<combatant_id> (duplicates allowed for stacking).
8 Handler POSTs to /attack (PC) or /npc_attack (NPC) with target_combatant_id + target_combatant_ids[].

Server-side

1 Endpoint reads body, validates auth + character ownership.
2 Action-economy gate (PC only): 409 over_budget if slot used and not override.
3 Range check (PC: _check_cast_range three-tier; NPC: _check_npc_attack_range no-bypass + override_range flag).
⚠ Returns 409 {error: "out_of_range", source_name, target_name, distance_ft, range_ft, spell_name} when too far.
4 Roll attack d20 + bonus with adv/dis from buffs (Rage advantage, Dodging disadvantage).
5 Roll damage (doubled on crit per RAW). Apply auto-uplifts (Hunter's Mark, Hex, Colossus Slayer — PC only).
6 Hit determination via _read_target_ac; if hit + auto_apply_damage, call _apply_damage_to_combatant.
7 For multi-target list, iterate per-id with fresh attack + damage rolls per RAW.
✓ Broadcast weapon_attack WS message → clients render chat card with verdict + damage + Undo.

Caster resolution — PC vs NPC

The picker needs to know the caster's token center to draw the ruler line and compute distances. PCs and NPCs use different lookups:

PC caster resolution walks tokens by character_id. NPC caster resolution walks the battle to find the combatant, then resolves the token via the same three-tier match the picker's commit path uses (source_token_id → token_template_id + name).

Caller-side API

Single-target spell / attack

const picked = await window.vttOpenMultiTargetPicker({
    required: 1,
    spellName: 'Fire Bolt',
    casterCharId: 42,           // PC caster
    rangeStr: '120 ft',         // parsed via _parseRangeFtJS
});
// picked === null         → user cancelled (Esc / right-click out)
// picked === ['tok_99']   → user picked one target combatant

Multi-target stacking (Magic Missile)

const picked = await window.vttOpenMultiTargetPicker({
    required: 3,                // L1 Magic Missile = 3 darts
    spellName: 'Magic Missile',
    casterCharId: 42,
    rangeStr: '120 ft',
});
// picked === ['tok_a', 'tok_a', 'tok_b']  → 2 darts on a, 1 on b

NPC attacker

const picked = await window.vttOpenMultiTargetPicker({
    required: 1,
    spellName: 'Scimitar',
    casterCombatantId: 'tok_501_demo',   // NPC, not casterCharId
    rangeStr: '5 ft',                    // melee — picker suppresses ruler line
});

Range enforcement — client + server

Range is enforced in two layers:

  1. Client-side warning — the picker draws the green ring only on in-range tokens, and the cursor / ruler turn amber when the cursor goes beyond the spell / attack's max reach. This is the visual gate; the player sees the problem before clicking.
  2. Server-side enforcement — endpoints (/attack, /cast_spell, /place_aoe, /npc_attack) re-check distance against the caster's actual token position and 409 with {error: "out_of_range", ...} if the client tried to send a too-far target. PCs honor a three-tier override (GM bypass / player override / strict mode); NPCs honor only an explicit override_range body flag (the GM acting as an NPC isn't allowed to bend the NPC's rules by default).
Why both layers. The client-side ring is the UX — players see range without trial and error. The server-side check is the authority — a buggy client, a touch-screen misclick, or a stale token position can't silently let an out-of-range cast through. The server is the source of truth.
