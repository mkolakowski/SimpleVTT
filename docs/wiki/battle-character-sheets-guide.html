Sheets in the Battle & Characters tabs v2.49.183

Visual reference for the mini-sheet that powers both the Battle tab (init tracker) and the Characters tab in the player drawer. Covers the layout anatomy, typography, color palette, the new v2.49.177-181 spell row chip system, and the PC-vs-NPC render-path split documented in PC vs NPC combat systems.

Two drawer tabs, one mini-sheet partial

Both the Battle tab (the init tracker with combatant cards) and the Characters tab (the full roster) render PC characters through the same Jinja partial: app/templates/_mini_sheet_card.html. NPCs in the Battle tab take a separate render path (buildMonsterInitSheet JS function in tabletop.html), but the visual conventions match — colors, fonts, chip styles all line up.

Top-to-bottom blocks

  1. Header (always visible) — Portrait disc on the left (token color as ring + first-letter glyph fallback), name + class line, "concentrating" sigil (🧿) when active, ▶ / ▼ collapse arrow on the right.
  2. Stat row — Compact "HP cur / max · AC · Spd" line in muted text. HP digits get the high-contrast color; everything else stays muted to keep the eye on changing values.
  3. HP bar — Single horizontal pill, green-to-amber-to-orange gradient so a visually low bar reads as "this PC is hurt" without needing the player to parse digits.
  4. Action-economy chip strip — Four chips (Act / Bns / Rxn / Mov). Lit (amber-tinted background) when used this turn; muted (gray) when unused. The movement chip shows feet remaining as digits.
  5. Section tabs — Actions / Spells / Abilities / Skills / Resources / Feats. Only tabs with content render; PCs with no spells skip Spells, characters with no resources skip Resources.
  6. Section content — Per-tab rows: attack/weapon rows, spell rows (the v2.49.177+ chip layout below), skill rows, ability rows, resource counters.

Spell row anatomy (v2.49.177-181)

Spell rows pack a lot of info into one line. Chip order is meaningful: name → metadata (class · range) → actionable (atk · dmg · save) → cast button. A glance-scan reads "what is this · what does it do · cast it."

Color logic. Metadata chips (range, class) use cool colors (teal, muted italic) — they're descriptive, not actionable. Actionable chips (atk, dmg, save) use warm and high-saturation colors (amber, pink, blue) so they read as "click here to do this." The cast button is purple to mark it as the primary CTA.

PC vs NPC mini-sheets

Both renderers share the visual language above. The render code paths differ because PCs have richer mechanics (spell slots, resources, death saves, class features) that NPCs don't model.

Behavior

Read-only vs editable

Mini-sheets are read-only for edits — to change HP, name, ability scores, or any sheet field, players open the full sheet via the 📋 Sheet button. The mini-sheet supports actions: clicking 🗡 Strike or 🪄 Cast fires the picker + endpoint; clicking a skill rolls it; clicking the HP digits opens an HP-edit popover.

Header click → collapse / expand

The header is a click target. Clicking anywhere on the header bar toggles the body open / closed. The ▶ / ▼ arrow on the right reflects current state. Collapse state is persisted to localStorage per-character per-tab via vtt_minisheet_open_<char_id> so a refresh restores what the player had open.

Tab state persistence

Each combatant remembers its last-selected tab via vtt_minitab_<combatant_id> in localStorage. Switching tabs on one PC doesn't affect another. NPC monster mini-sheets use the combatant id, not the template id, so three bandits sharing one TokenTemplate keep their tab state independent.

WebSocket sync

HP edits via the full sheet broadcast character_hp_update; the mini-sheet handler updates the HP digits + bar in real time. Color / portrait changes broadcast similar deltas. The mini-sheet doesn't need a page refresh to pick up changes from anywhere in the app.
