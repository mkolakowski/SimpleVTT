# SimpleVTT — Bug Tracker

The single canonical list of known defects, RAW divergences, latent test-coupling hazards, and stale-doc bugs. Forward-looking *features* live in [`TODO.md`](TODO.md); *shipped* work lives in [`TODONE.md`](TODONE.md). This file is for things that are **wrong** (or known-fragile) today.

> **Why this file exists.** Bugs used to be scattered across `TODO.md`'s "Test Infrastructure" / "Class Features" sections and inline `**Status:**` notes in `docs/plans/*.md`. This tracker consolidates them so there's one place to scan. Plan docs may still carry an inline note where the bug is a *deferred design decision*, but the authoritative entry — severity, repro, fix paths — lives here.

**Severity legend:**

| Tag | Meaning |
|-----|---------|
| 🔴 P1 | Breaks a user-facing flow or masks regressions in CI; fix soon. |
| 🟡 P2 | Real defect with a workaround or local-only coverage; schedule it. |
| 🟢 P3 | Cosmetic, stale-doc, RAW divergence accepted for v1, or latent hazard not yet triggered. |

**Status vocabulary:** `OPEN` · `NEEDS-VERIFY` (likely fixed, awaiting confirmation) · `WONTFIX` (accepted divergence) · `FIXED` (move to TODONE on close).

**Fix (v2.1033.7 "The Airlock"):** the autouse `hermetic_pcs` fixture in `tests/harness/conftest.py` snapshots each demo PC's pristine top-level mutable sheet fields (`spells`/`spell_slots`/`resources`/`attacks`/`abilities`/defenses/…) on the first test and PATCHes back any that drifted before every subsequent test — so a sheet-mutating test whose own restore doesn't complete can no longer cascade. `test_hermetic_pcs.py` guards the mechanic. Scope is top-level keys only (those round-trip through a bare `/sheet-fields` PATCH; `/rest`'s normalize doesn't recompute them); class-scoped `level`/`subclass` drift is left out — see B18.

**Source:** split out of B16's post-fix CI triage (run `29792242048`). In the CI `harness` job — which runs the whole non-catalog suite serially against one demo stack — **4715 of 4829 tests fail** with uniform state-corruption signatures: "No Ki / Lay on Hands / Channel Divinity / Action Surge resource on this sheet", "Thalindra has no Fireball", "Spell not found", "assert 5 == 7". **Why it never showed on the dev host:** the full ~4800-test serial run takes hours and was never done locally — only isolated subsets, which start from clean demo state. **Fix (substantial, own effort):** make the sheet-mutating tests hermetic — the cleanest is an autouse fixture that snapshots each touched PC's full sheet and restores it in teardown (superset of `clean_pcs`), so a failed in-test restore can't cascade. Alternatively bisect the CI run for the specific poisoner(s). Until then the `harness` CI job is uninformative in bulk — read `spell-catalog` (green) as the real signal. **Not app regressions.** Related order-dependence: B16 cluster 1 (leaked ambient), and the `clean_pcs` design note in `conftest.py`.
