Overall ~97%. Magic items joins Monsters + Class features + Races as a strictly-✅ surface after the v2.403.0–v2.404.0 magic-items closure arc — 22 charge-bearing Bucket D items + both Bucket A holdouts (wind-fan, medallion-of-thoughts) wired through the new _use_item_action_announce_only + dedicated handlers (Phase 9.2), plus the 4 umbrella catalog slugs closed in v2.404.0 (potion-of-healing real heal handler with tier picker, spell-scroll real cast handler, weapon-1-2-or-3 + wand-of-the-war-mage-1-2-or-3 passive stubs — Phase 9.3). Spells moved ~79% → ~83% via the v2.404.1–v2.404.10 spell utility-upcast arc: nine target-scaling utility spells (Invisibility, Fly, Enhance Ability, Longstrider, Charm Person, Bane, Command, Animal Friendship, Blindness/Deafness) now ride the v2.380.0 / v2.381.0 cap-extension substrate across both _SPELL_BUFF_MAP and _SPELL_TARGET_CAPS. Prior arcs that already shipped: the v2.392.0–v2.399.2 race-features arc (Dragonborn Breath Weapon, Tiefling racial Hellish Rebuke, Hill Dwarf Stonecunning + heavy-armor speed bypass, Rock Gnome Artificer's Lore, plus recognition flags for Halfling Nimbleness + Naturally Stealthy); magic-item content tail (v2.316–v2.344); class-feature strictly-✅ 100% (Aura of Courage v2.368.0; Unarmored Defense / Deflect Missiles / Cleansing Touch v2.369.0–v2.370.1); AoE auto-targeting (sphere/cone/line picker + cast_spell parity v2.373.0–v2.376.0); the lair-action arc end-to-end (v2.377.0–v2.382.0: metallic + Lich + Kraken backfill + condition map + regional effects); and the condition-enforcement audit (v2.385.0–v2.391.0: Sneak Attack ally-skip + 3 PC-action incapacitated gates + Grappled-ends-on-grappler-incap + Charmed-can't-target-charmer). The remaining ~3% is content-layer utility-spell richness (~250 cast-and-broadcast spells with no damage/healing base) + permanently-GM-narrated condition clauses by design. Known defects are tracked in BUGS.

Security spine (shipped, v2.42x)

Three sibling design plans filed v2.423.3 → v2.423.5 that compose into one end-to-end abuse-detection-and-banning pipeline for operators running SimpleVTT on a public box. Each plan ships independently, but designed together: SimpleVTT emits canonical log lines → CrowdSec parses them → Cloudflare bans at the edge → an attacker never reaches the FastAPI layer again. All three have shipped (demo magic-link Phases 1+1B v2.425.0/v2.430.0; fail2ban/CrowdSec Phases 1+2 v2.426.0/v2.429.0; Cloudflare edge-banning Phase 1 v2.427.0, extended through v2.531.0).

  • Demo magic-link login — URL-based passwordless login for the demo instance only, double-env-var gated so a compromised admin account can't enable it against production. HMAC-signed single-use tokens, 15-min TTL.
  • fail2ban / CrowdSec log integration — canonical structured log lines (<event> ip=… ua=… …) + reference fail2ban filter.d/jail.d and CrowdSec parsers/scenarios configs shipped in-repo so operators get drop-in banning detection. Same canonical lines power both engines.
  • Cloudflare edge-banning — outbound API client + GM-only "Ban IP at edge" button + generic admin_audit_log table. Wiremock-in-compose for dev per the third-party-API rule. Pairs with the CrowdSec → Cloudflare bouncer path.

Tracked together in the Security section of TODO.md.

Contributing guides

A guide entry lives at docs/wiki/<slug>.{md,html} and gets a row in the "Available guides" table above. Each guide should:

  • Open with a one-sentence summary of what it covers + audience.
  • State the version it was written for (so future readers can date the screenshots / examples).
  • Include code-location pointers for anything in the codebase the reader might want to grep.
  • For HTML mocks: be self-contained (inline CSS, no external assets) so it opens with file:// and survives moves. The server injects the v2.49.9 wiki nav after <body> at request time — don't bake it into the file.

When you add a guide, a plan, or a reference doc: update docs/wiki/README.md, app/templates/wiki.html (the table on this page), and (for plans/refs/repo docs) the allowlist in app/routes/wiki_routes.py so the new doc is reachable through the wiki nav.
